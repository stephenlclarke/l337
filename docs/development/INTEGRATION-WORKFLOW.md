# Integration and validation workflow

The current [agent rules](../../AGENTS.md) and [Makefile](../../Makefile) define validation. Default `make ci` requires normal tests, full inventory and coverage validation, zero leaks and static/tooling checks. ASAN and TSAN are optional manual diagnostics, off by default including hosted CI. `make threads` and `make address` retain the original whole-suite commands; `ELITE_SANITIZERS=1 make ci` opts into both after normal checks. Sanitizer preparation, shards and local-proof bridges are not prerequisites for normal CI or delivery.

G1 owns native execution. Coordinate the existing lease through Root and preserve assigned source, actual runner authorization, resource guards and evidence. Independent source/result review, final-head required checks and approvals, protected merge and release gates remain required. Publish SonarQube analysis only from a committed main branch with its exact commit SHA as `projectVersion`. README media must be generated by the game renderer with `make readme-media`.

A reviewed change with authored UNRUN tests remains validation pending. Prepared source, a passing focused unit cohort, a usable local build and a published signed release are different delivery states. Record their actual commits and evidence separately in the [completion ledger](../COMPLETION-LEDGER.md).

The complete [October integration and diagnostic history](../archive/checkpoints/INTEGRATION-WORKFLOW-202610.md) retains unique failure observations, physical paths, consumed counters and acceptance boundaries. It includes superseded mandatory sanitizer campaigns and review instructions; these do not define current workflow or transfer execution authority. Do not relabel an incomplete or historical result as a current pass.
