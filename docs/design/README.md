# Design and audit inputs

These JSON contracts and dated audits retain requested gameplay, equipment, physics and graphics behavior. They are requirements and source evidence, not claims that the complete design has shipped. Start with the [design index](DESIGN-INDEX.json), then use the [completion ledger](../COMPLETION-LEDGER.md) for actual implementation, qualification and blockers.

The [station finance design](STATION-FINANCE-DESIGN.md) retains owner, debt, repayment and acceptance rules. [Gameplay](GAMEPLAY-SYSTEMS-DESIGN.json), [salvage](SALVAGE-GAMEPLAY-DESIGN.json), [component progression](COMPONENT-PROGRESSION-DESIGN.json) and [equipment purchase progression](EQUIPMENT-PURCHASE-PROGRESSION-DESIGN.json) retain physical, finite-stock, receiving, fitting and save requirements. Original source paths and hashes inside dated evidence remain provenance, even where the live document has moved; use the [relocation/coverage table](../development/DOCUMENTATION-COVERAGE.csv) to locate it.

[Original fleet contracts](../fleet-design-v2/README.md), [current hull bindings](../player/ORIGINAL-FLEET.md), [research](../research/README.md) and [archived checkpoints](../archive/README.md) have distinct authority. Generated model research inputs remain available here to the importer; moving them does not regenerate or activate game resources. [Documentation home](../README.md).
